유튜브 임베드 오류 153 원인과 해결: Referrer-Policy 한 줄

2026.09.27 · 베일드 솔루션

제품 페이지에 시연 영상을 넣었더니 재생 버튼을 누르자마자 "동영상 플레이어 구성 오류, 오류 153"이 떴습니다. 유튜브에서는 멀쩡히 재생되는 공개 영상이고, 퍼가기 허용도 켜져 있었습니다. 원인은 영상이 아니라 우리 사이트의 보안 헤더였습니다. 증상과 해결 방법을 정리합니다.

증상

  • 유튜브 사이트에서 직접 열면 정상 재생됩니다.
  • 우리 페이지의 iframe 안에서만 "오류 153"이 뜹니다.
  • 같은 코드를 로컬 HTML 파일이나 다른 사이트에 넣으면 재생되는 경우가 있습니다.

마지막 항목이 힌트입니다. 코드가 같은데 사이트에 따라 결과가 다르다면, 페이지가 보내는 헤더를 의심해야 합니다.

원인: 유튜브가 리퍼러를 받지 못함

유튜브 임베드 플레이어는 재생을 시작할 때 어느 사이트에서 불렀는지를 확인합니다. 브라우저는 이 정보를 Referer 헤더로 보내는데, 페이지의 Referrer-Policy가 엄격하면 다른 도메인으로는 Referer를 아예 보내지 않습니다.

보안 점검 도구들이 흔히 권하는 Referrer-Policy: same-origin이나 no-referrer가 바로 그런 설정입니다. 같은 사이트 안에서만 Referer를 보내므로 youtube.com 쪽에는 빈 값이 갑니다. 유튜브는 출처를 알 수 없는 임베드 요청을 거부하고, 그 결과가 오류 153입니다.

즉, 보안 헤더를 꼼꼼히 설정한 사이트일수록 이 오류를 만나기 쉽습니다. 사이트 설정을 바꾼 뒤 멀쩡하던 영상이 갑자기 안 나온다면 가장 먼저 확인할 부분입니다.

확인 방법

  1. 브라우저 개발자 도구의 네트워크 탭을 열고 영상 페이지를 새로 고칩니다.
  2. 우리 페이지 문서 요청의 응답 헤더에서 Referrer-Policy 값을 봅니다.
  3. youtube.com 또는 youtube-nocookie.com으로 가는 embed 요청을 눌러 요청 헤더에 Referer가 있는지 확인합니다. 없다면 원인이 맞습니다.

해결: iframe에만 정책을 따로 준다

사이트 전체의 정책을 느슨하게 바꿀 필요는 없습니다. iframe 태그에 referrerpolicy 속성을 주면 그 요청에만 다른 정책이 적용됩니다.

<iframe
  src="https://www.youtube-nocookie.com/embed/VIDEO_ID?autoplay=1"
  title="제품 시연 영상"
  referrerpolicy="strict-origin-when-cross-origin"
  allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
  allowfullscreen>
</iframe>

strict-origin-when-cross-origin은 다른 도메인에 전체 주소가 아니라 도메인만 보냅니다. 페이지 경로나 검색어 같은 정보는 넘어가지 않으므로 보안상 손해가 거의 없고, 유튜브는 출처를 확인할 수 있게 됩니다. 브라우저 기본값도 이 값입니다.

React에서는 속성 이름이 referrerPolicy(카멜 표기)입니다. 소문자로 쓰면 경고 없이 무시되는 경우가 있으니 주의합니다.

덤: 클릭하기 전에는 iframe을 넣지 않기

유튜브 iframe 하나는 스크립트와 리소스를 수백 KB 이상 불러옵니다. 제품 페이지처럼 첫 화면 속도가 중요한 곳이라면 처음에는 썸네일 이미지와 재생 버튼만 보여 주고, 클릭했을 때 iframe으로 바꾸는 방식이 좋습니다.

  • 썸네일은 https://i.ytimg.com/vi/VIDEO_ID/maxresdefault.jpg를 쓰고, 고화질 썸네일이 없는 영상을 위해 hqdefault.jpg로 대체하는 처리를 넣습니다.
  • 클릭 후 불러오는 iframe에도 위의 referrerpolicy를 똑같이 넣어야 합니다. 이 방식으로 바꾸면서 속성을 빠뜨려 오류가 다시 생기는 경우가 많습니다.
  • 검색 결과에 영상이 잡히게 하려면 페이지에 VideoObject 구조화 데이터(업로드 날짜, 길이, 썸네일, 임베드 주소)를 따로 넣습니다. iframe이 처음에 없으니 구조화 데이터가 영상의 존재를 알려 주는 역할을 합니다.

정리

  • 오류 153은 대부분 영상 문제가 아니라 페이지가 Referer를 보내지 않아서 생깁니다.
  • 사이트 전체 정책은 그대로 두고, 유튜브 iframe에만 referrerpolicy="strict-origin-when-cross-origin"을 줍니다.
  • 클릭 후 로드 방식을 쓰면 속도를 지킬 수 있고, 구조화 데이터로 검색 노출도 챙길 수 있습니다.
